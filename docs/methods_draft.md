## 2 System, Methods, and Usage

Meta2Data is an end-to-end command-line pipeline for the automated retrieval, processing, and cross-study integration of 16S rRNA amplicon sequencing data from public repositories, implemented in Python 3 and Bash without containerisation. The pipeline comprises three sequential modules—MetaDL, AmpliconPIP, and ggCOMBO—unified under a single `Meta2Data` entry point with coupling support from the QIIME2 amplicon platform, using a standardised CSV metadata table as the inter-module handoff requiring no manual file conversion. MetaDL implements a per-project JSON checkpoint and AmpliconPIP maintains fastp-based resume checkpoints, enabling both modules to skip completed datasets and resume automatically on re-invocation. Meta2Data is provided as open-source software deployable on any Linux system by cloning the repository and adding its `bin/` directory to `PATH`; AmpliconPIP and ggCOMBO additionally require the QIIME2 amplicon distribution 2024.10 conda environment. The pipeline runs on local workstations and HPC clusters (SLURM, PBS), with required native binaries (vsearch 2.30.0 and fastp 0.24.0) and Python dependencies auto-installed on first invocation. Network connectivity is required on first invocation to query the NCBI Entrez and CNCB APIs and fetch reference databases; downloaded taxonomy databases are cached locally and reusable offline via `--db`. The Meta2Data source code and documentation are freely available at https://github.com/LinyangSun/Meta2Data.

Meta2Data lowers the barrier to large-scale comparative meta-analyses of public 16S rRNA amplicon data by automating database queries, raw-read processing, and cross-study integration steps that conventionally require manual coordination across multiple specialised tools and APIs. These processes cover metadata retrieval and standardisation, sequencing platform detection, raw data download, multi-platform amplicon quality control and denoising, cross-study dataset merging, taxonomy classification, and phylogenetic tree construction. The pipeline culminates in QIIME2-compatible feature tables and taxonomy artefacts ready for downstream diversity analyses.

Bioinformatic processes executed by Meta2Data (Table 1) are active by default in every pipeline run. Individual modules can be selectively skipped or re-executed via command-line flags without restarting the entire pipeline. Optional steps—such as SEPP-based phylogenetic tree construction and tree-based feature filtering—are attempted in every ggCOMBO run but do not terminate the pipeline on failure, with a warning issued in their place. Each module integrates a combination of custom Python scripts, Bash orchestration, and QIIME2 plugin calls into a unified processing chain. The selection of a denoising strategy for each dataset is determined by sequencing platform—resolved from NCBI Entrez or CNCB metadata during a single batch pre-processing step—and is reported in the Module column of Table 1. Short-read denoising has been validated with data generated by Illumina and Ion Torrent instruments; Roche 454 data are processed through a separate vsearch-based OTU clustering path; PacBio SMRT CCS data are handled via a dedicated long-read denoising module; Oxford Nanopore data are explicitly unsupported.

*Table 1. Processes of Meta2Data in operation order.*

| Process (in operation order) | Module | Tool(s) |
|---|---|---|
| Keyword / BioProject ID search | MetaDL | NCBI Entrez, CNCB API |
| Metadata download and standardization | MetaDL | Biopython, requests |
| Sequencing platform detection | AmpliconPIP | NCBI Entrez, CNCB API |
| Raw data download | AmpliconPIP | Aspera / SRA FTP / CNCB |
| Adapter removal | AmpliconPIP | fastp 0.24.0 |
| Primer detection and trimming | AmpliconPIP | entropy_primer_detect.py |
| Illumina / Ion Torrent denoising | AmpliconPIP | DADA2 (QIIME2) |
| Roche 454 OTU clustering | AmpliconPIP | vsearch 2.30.0 (QIIME2) |
| PacBio SMRT CCS denoising | AmpliconPIP | DADA2 denoise-ccs (QIIME2) |
| Feature table and sequence merging | ggCOMBO | QIIME2 feature-table |
| Sequence orientation | ggCOMBO | RESCRIPt (QIIME2) |
| Taxonomy assignment | ggCOMBO | Naïve Bayes classifier (QIIME2) |
| Phylogenetic tree construction | ggCOMBO | SEPP fragment insertion (QIIME2) |
| Tree-based feature filtering | ggCOMBO | QIIME2 fragment-insertion |

The primary Meta2Data pipeline accepts either a directory of plain-text BioProject ID files—supporting PRJNA, PRJEB, PRJDB, and PRJCA prefixes covering NCBI, ENA, DDBJ, and CNCB—or a structured keyword query combining field, organism, and optional terms. MetaDL downloads SRA RunInfo and BioSample attribute tables via NCBI Entrez efetch or the CNCB GSA portal, merges records on shared BioSample identifiers, and normalises all column names to CamelCase via a configurable rename dictionary, producing a consolidated all_metadata_merged.csv that requires no manual reformatting before being consumed by AmpliconPIP. Before dispatching datasets to sub-pipelines, AmpliconPIP performs a batch platform detection query against NCBI Entrez and CNCB metadata for all pending projects in a single pre-processing step, preventing API rate-limit exhaustion during parallel execution. Adapter sequences are subsequently removed with fastp 0.24.0 with quality and length filtering disabled, ensuring that only technical adapter contamination is stripped prior to primer detection. Primer sequences are identified and trimmed by entropy_primer_detect.py, which constructs a 60 × 4 position-wise base frequency matrix from the first sample, labels each position as Conserved (f₁ ≥ 0.80), Degenerate (f₁+f₂ ≥ 0.80, f₂ ≥ 0.10), or Variable, and matches the longest [CD]* prefix against nine forward and thirteen reverse consensus sequences spanning V1–V9. Trimmed reads are routed to platform-specific denoising: Illumina data use DADA2 denoise-paired with automatic PE-to-SE fallback if read-pair retention falls below 50%; Ion Torrent data use DADA2 denoise-pyro with a 10 bp 5′ trim; PacBio SMRT CCS data use DADA2 denoise-ccs with 27F/1492R primers; and Roche 454 data use a vsearch-based pipeline of adaptive tail trimming, 97% de novo OTU clustering, and chimera removal. For QIIME2-based taxonomy assignment, users can specify any of three supported reference databases via --db-type—GreenGenes2 2024.09, SILVA 138.99, or GSR-DB—or allow the pipeline to automatically download and validate the selected database with --dl on first invocation.

A pre-trained Naïve Bayes classifier (qiime feature-classifier classify-sklearn) and SEPP fragment insertion (qiime fragment-insertion sepp) serve as the two primary tools for taxonomy assignment and phylogenetic placement, respectively. Taxonomy assignment accuracy and resolution are directly dependent on the choice and completeness of the reference database used. In Meta2Data with access to the external internet, the default pipeline automatically downloads and validates all required database files with --dl—including a GSR-DB classifier trained locally against QIIME2 2024.10's scikit-learn version on first invocation—from their respective public repositories. Users can adjust the confidence threshold for taxonomy assignment via --confidence (default 0.7), balancing classification specificity against recall according to the diversity and completeness of the reference database. Meta2Data includes multiple mechanisms to ensure cross-study taxonomic and phylogenetic consistency, including automated read orientation correction via qiime rescript orient-seqs and filtering of merged feature tables to retain only SEPP-placed features. Alternatively, previously downloaded databases can be supplied directly via the --db parameter if the deployment environment lacks internet access or a custom reference database is required. Phylogenetic tree construction via SEPP is included by default but is non-fatal; if fragment insertion fails, the pipeline issues a warning and retains taxonomy-annotated feature tables, ensuring that non-phylogenetic diversity analyses remain available.
